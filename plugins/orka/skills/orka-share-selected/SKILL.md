---
name: orka-share-selected
description: Share or update one explicitly selected local session, memory, plan, instruction file, or complete skill with an Orka team, even when automatic category sharing is off.
---

# Share a selected snapshot

Use this workflow only when the user asks to share or update particular content. Reading project context, finishing a turn, or preparing a handoff is not a sharing request. Sharing existing local snapshots requires the running Orka desktop app and a compatible service. Creating new shared memories and updating plans have their own tools.

1. Call `get_connection_status` and resolve project/repository IDs with `list_projects`. All tools use the signed-in desktop account. If pending, ask the user to review the request in Orka Settings → Connectors; if signed out, sign in through Orka. Denied, revoked or stale sessions require reconnecting from the assistant and explicit native approval. Account/service changes invalidate earlier sessions even after switching back. There is no separate plugin login or remote fallback. Supply the selected project ID; the desktop injects account and service internally. Never supply credentials, switch accounts or fabricate authority to bypass a refusal. Selected publication requires `orka.read` and `orka.write`, plus current project authority; missing scopes require a new explicitly approved session.
2. Call `list_local_resources` for the requested category, project, and repository. Include the native session ID when the host provides it. Follow `nextOffset` using `offset` while locating the requested item. A title, active marker, or most-recent timestamp alone does not identify the current conversation. Ask the user to select an item if identity is ambiguous. Never silently publish another session, repository, or an entire category.
3. Call `preview_share` with the selected resource ID and kind. Explain the item, snapshot size and included files when useful. This freezes the exact snapshot through that moment; later edits and future conversation turns are excluded. ENV files and arbitrary paths cannot be shared through this workflow. Share complete skill packages, not just their entry file.
4. For a Pi session (provider `pi` in the catalog), explain that project members with access will receive the complete saved tree, including abandoned branches and any tool activity or reasoning omitted from the reader. When the preview includes `piScope`, report `entries` and `offBranchEntries`. Ask whether the user wants to share that complete snapshot unless their request explicitly authorized this full scope for the selected session. A request to share the visible conversation alone calls for a text handoff. If the preview expires or changes, review the fresh snapshot with the user before sending.
5. If the user authorized the identified snapshot, call `share_selected` with its `previewToken`. For a Pi preview with `piScope`, also pass that same token as `acknowledgedPiPreviewToken`. Automatic sharing being off does not require extra confirmation. Follow the host's actual permission prompts. If the user requested only a preview, stop at the preview. Never enable automatic category sharing.
6. Report the actual status. `published` means the service accepted the snapshot; `approval_required` means an existing project policy requires owner review; `queued` means the frozen snapshot is saved locally for retry; `conflict` requires resolution before claiming an update. A queued request is not a completed share. Keep the request ID for safe retries; repeating the same preview token must not create another publication.

For “update the shared session”, preview its current local snapshot again and submit that new token. Sharing once does not authorize future turns. Ordinary automatic sharing continues only for categories the user has enabled in the app. Existing permissions, source provenance, account isolation, and review requirements always apply. If local tools or the desktop app are unavailable, explain that this sharing action requires the desktop integration; do not claim remote tools uploaded this local snapshot.
